# ResourceHub PRD（产品需求摘要）

> 与 [DESIGN.md](./DESIGN.md) 配套；本文件偏「做什么 / 为谁做」，设计细节见设计方案。  
> 状态：Draft · 版本：0.1

---

## 一句话

ResourceHub 是一个多服务器资源监控系统：各机部署轻量 Agent，统一在 Web 上看 CPU / GPU / 内存 / **磁盘容量**等，并在资源紧张时告警——**采集与查询都必须低开销，尤其禁止用耗时扫盘拖慢业务机**。

---

## 问题陈述

- 机器多了以后，靠 SSH + 临时命令看资源不可扩展  
- 磁盘「还剩多少」本应很快，但很多人用 `du` 导致查询又慢又伤 IO  
- 需要统一历史趋势与阈值告警，而不是点状排查  

---

## 用户与场景

| 角色 | 典型场景 |
|------|----------|
| 运维 / SRE | 早班巡检：哪些机器磁盘将满、GPU 是否空闲、Agent 是否掉线 |
| 算法 / 训练 | 找空闲 GPU 机器；确认训练机磁盘与显存 |
| 研发负责人 | 容量趋势，决定是否扩容 |

### 核心用户故事

1. 作为运维，我希望在 3 秒内看到所有机器的 CPU/内存/最满磁盘%，以便发现异常。  
2. 作为运维，我希望磁盘容量数据来自轻量采集，**不会因为看板刷新而触发全盘扫描**。  
3. 作为用户，我希望 Agent 掉线或磁盘超过阈值时收到告警。  
4. 作为管理员，我希望用安装脚本 + token 接入新机器，无需改服务端代码。  
5. 作为运维，当某盘告警将满时，我希望分层看到最大的目录/用户，以便定位清理对象。  
6. 作为管理员，我希望对 `/home/<user>/<folder>` 配置容量上限，**超限时告警/提醒**（软限制，不阻止写入）。

## 需求优先级

### P0（MVP 必须有）

- [ ] 多机注册与在线状态  
- [ ] CPU、内存、磁盘**挂载点容量**（statfs / 等价快速 API）  
- [ ] Web 总览 + 单机详情（最新值）  
- [ ] 磁盘使用率、Agent 掉线告警  
- [ ] Agent 推送指标；API 只读已存储数据  

### P1

- [ ] GPU（NVIDIA）利用率与显存  
- [ ] 短时历史曲线  
- [ ] 机器分组 / 标签  
- [ ] CPU / 内存 / GPU 阈值告警  

### P2

- [ ] 目录级空间分析：异步 Top-N 下钻，定位大户（路径 / owner）  
- [ ] 用户目录**软配额**：按 path 模板限制「每文件夹」大小，超限告警/提醒（不拦写）  
- [ ] 通知渠道集成  
- [ ] 更细权限与审计  

详见 [STORAGE_ATTRIBUTION_AND_QUOTA.md](./STORAGE_ATTRIBUTION_AND_QUOTA.md)。

## 成功指标

| 指标 | 目标 |
|------|------|
| 总览页加载（≤ 100 台） | < 2s 出首屏有效数据 |
| 单机快路径采集 P99 | < 200ms（无 GPU） |
| 磁盘容量采集 | 基于 O(1) 文件系统查询，P99 < 50ms（≤16 挂载点） |
| 误用重 IO 扫盘 | 热路径出现次数 = 0（评审 + 测试门禁） |

---

## 明确不做

- 远程命令执行 / 自动清理磁盘  
- OS 硬配额 / 拦截写入 / 超限自动删除（目录限额**仅软告警与提醒**）  
- 替代全链路 APM、日志检索  
- MVP 阶段的目录级实时 `du`  

---

## 依赖与假设

- 目标机可安装常驻 Agent，并可访问 Server 的上报地址  
- 首期以 Linux 为主  
- 用户能接受「看板数据有 5～15 秒延迟」（采集间隔导致）
